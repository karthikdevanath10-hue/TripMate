How Data Encapsulation Works in the Payment Class

During your project viva, your evaluator can inspect the com.tripmate.model.Payment class:

// 1. Private fields hide critical financial data private final double advanceAmount = 200.0; private String paymentStatus; // "PENDING" or "SUCCESS" private String transactionId; // 2. Controlled method is the ONLY way to change paymentStatus public boolean processPayment(String txId) { if (txId != null && txId.trim().length() >= 6) { this.transactionId = txId.trim(); this.paymentStatus = "SUCCESS"; return true; } return false; } // 3. Safe read-only getters public double getAdvanceAmount() { return advanceAmount; } public String getPaymentStatus() { return paymentStatus; }

Why this is Encapsulation: External classes cannot directly assign payment.paymentStatus = "SUCCESS" or tamper with advanceAmount. All mutations are validated and channeled through the public method processPayment().

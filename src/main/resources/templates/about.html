Project Overview

TripMate is a modern web-based smart trip planning application developed using Java, Spring Boot, Spring MVC, and Thymeleaf. Rather than hardcoding fixed trips, TripMate dynamically analyzes user preferences, party size (solo vs. group), and travel budgets in Indian Rupees (&inr;) to recommend the best matching destinations with day-by-day itineraries and an advance booking verification module.

Key Object-Oriented Programming (OOP) Concepts

Top Evaluation Requirement

1. Data Encapsulation (Crucial)

Definition: Data Encapsulation is the mechanism of wrapping data (variables) and the methods that operate on that data into a single unit (class), while hiding the internal state of the object by declaring variables as private.

How It Is Implemented in Payment.java:
  • All fields are private: advanceAmount, paymentStatus, transactionId, and paymentDate cannot be directly accessed or tampered with from outside the class.
  • No Public Setters for State: There is deliberately NO setPaymentStatus() or setAdvanceAmount().
  • Controlled Mutation via Method: The only authorized route to mark payment as SUCCESS is by invoking processPayment(String transactionId) with valid input parameters.
  • Read-Only Public Getters: External callers can inspect the status and advance amount safely through getPaymentStatus() and getAdvanceAmount().
Viva Question: "Why did you not provide a setter for paymentStatus?"
Answer: "To prevent external classes or malicious tampering from changing a payment status to SUCCESS without proper verification of a valid transaction ID. This guarantees state encapsulation and data integrity."
// com.tripmate.model.Payment.java public class Payment { private String paymentId; private final double advanceAmount = 200.0; private String paymentStatus; private String transactionId; // Controlled mutation method public boolean processPayment(String txId) { if (txId != null && txId.trim().length() >= 6) { this.transactionId = txId.trim(); this.paymentStatus = "SUCCESS"; return true; } this.paymentStatus = "FAILED"; return false; } // Safe read-only getters public double getAdvanceAmount() { return advanceAmount; } public String getPaymentStatus() { return paymentStatus; } }
OOP Concept

2. Inheritance

Definition: Inheritance allows a subclass to acquire attributes and behaviors from a superclass, fostering code reuse and defining a clear class hierarchy.

Class Hierarchy:
  • Superclass: Trip (abstract class) declares shared fields: tripId, user, destination, totalBudget, and concrete methods like calculateRemainingBudget().
  • Subclasses:
    • SoloTrip extends Trip: Specializes behavior for an individual traveler.
    • GroupTrip extends Trip: Specializes behavior for multiple travelers, room pooling, and pooled vehicle transit.

3. Polymorphism

Definition: Polymorphism ("many forms") allows a method to exhibit different behaviors based on the runtime instance invoking it. In Java, dynamic method dispatch enables invoking overridden subclass methods via a superclass reference.

Overridden calculateTotalCost() Method:
  • SoloTrip implementation: Cost is strictly 1x destination estimate per person.
  • GroupTrip implementation: Dynamically calculates shared double-occupancy hotel rooms: Math.ceil(travellers / 2.0) and shared transport scaling factors.
  • Polymorphic invocation: Trip trip = activeTrip; double cost = trip.calculateTotalCost(); The caller does not need to know whether the instance is a SoloTrip or GroupTrip; Java executes the appropriate method at runtime!
// Polymorphic dispatch in TripService / Controller Trip trip = (user.isGroup()) ? new GroupTrip(id, user, dest, budget) : new SoloTrip(id, user, dest, budget); // Dynamic method dispatch executes subclass implementation double total = trip.calculateTotalCost();
OOP Concept

4. Abstraction

Definition: Abstraction hides complex internal implementation details and exposes only essential operations through interfaces and abstract classes.

Implemented Through Interfaces:
  • public interface PaymentService defines high-level payment contracts: initiatePayment(), validateTransactionReference(), and processPayment().
  • DemoPaymentService implements PaymentService provides the concrete demo implementation for the college demonstration.
  • In the future, a real RazorpayService or StripeService can implement PaymentService without altering any controller or business logic.
public interface PaymentService { Payment initiatePayment(); boolean validateTransactionReference(String ref); boolean processPayment(Payment p, String ref); } public class DemoPaymentService implements PaymentService { // Concrete implementation }
Presentation Checklist for College Evaluator
  1. Start at Home Page (http://localhost:8080/) — show branding, navigation, and popular destinations.
  2. Click "Plan a Trip" — show the choice between Solo Trip and Group Trip.
  3. Fill traveler details and enter a budget (e.g. ₹15,000 for solo or ₹30,000 for group).
  4. Show the Destination Recommendations generated by Java budget-matching logic.
  5. Select a destination (e.g. Mysore) and show the generated 3-Day Itinerary with expense breakdown.
  6. Click "Proceed to Advance Payment" — show the demo QR code and open Payment.java in IDE to demonstrate Data Encapsulation.
  7. Click "Quick Fill Demo Transaction ID" and confirm payment — show the final Booking Confirmation Voucher with unique Booking ID.
  8. Click "Print Voucher" to demonstrate receipt generation.
